# إعداد 10.0 — نسخة المدرسين المتعددين (GitHub Pages + Supabase)

**الحالة:** إصدار تجريبي تقني يتطلب إعداد مشروع Supabase واختبارات أمنية حقيقية قبل إتاحته للمدرسين. لا تستخدم بيانات طلبة حقيقية قبل نجاح اختبارات العزل والحفظ.

## ما الذي تغير؟

- تسجيل حساب مستقل لكل مدرس بالبريد وكلمة المرور، مع تأكيد البريد وإعادة تعيين كلمة المرور بحسب إعدادات Supabase.
- لكل حساب مساحة بيانات منفصلة `public.teacher_workspaces` مرتبطة بـ `auth.users.id`.
- حماية القراءة والإضافة والتعديل في قاعدة البيانات بسياسات Row Level Security. لا توجد صلاحية قراءة أو كتابة للزائر غير المسجل.
- نسخ الدروس والدرجات والاختبارات والغياب والتقويم إلى مساحة المدرس السحابية نفسها.
- عدم حفظ أسماء الطلبة والدرجات الجديدة نصاً واضحاً في `localStorage`؛ تبقى في الذاكرة حتى التأكد من التخزين السحابي.
- لا ينقل التطبيق بيانات الإصدار القديم دون تأكيد المدرس. يمكن لاحقاً حذف النسخة القديمة من التخزين المحلي.
- عند تغيير البيانات من جهازين في وقت متزامن، يكتشف تعارض `revision` ويتوقف قبل استبدال أحد التعديلين، ويتيح نسخة JSON للحفظ اليدوي.

## إعداد أول مرة (مسؤول التطبيق فقط)

1. أنشئ مشروعاً في https://supabase.com/dashboard . اختر منطقة استضافة ملائمة ومتوافقة مع سياسات خصوصية المدرسة، واحفظ كلمة مرور قاعدة البيانات بطريقة آمنة.
2. افتح **SQL Editor** داخل Supabase. الصق محتويات `supabase_setup.sql` كاملة واضغط **Run**. **لا تنفذ SQL على مشروع يحوي جدولاً آخر باسم `teacher_workspaces` قبل مراجعته.**
3. افتح **Authentication → Providers → Email**. فعّل تسجيل الدخول بالبريد وكلمة المرور وتأكيد البريد (مستحسن). لا تفعّل حسابات مجهولة إذا لم تكن بحاجة لها.
4. افتح **Authentication → URL Configuration** وضع:
   - Site URL: `https://attest313.github.io/idad-mobile/`
   - Redirect URL: `https://attest313.github.io/idad-mobile/`
   - أضف عنوان التجربة الإضافي فقط إن كنت تستخدمه فعلاً.
5. في **Project Settings / Connect / API Keys** انسخ **Project URL** و**Publishable key** (`sb_publishable_...`) إلى `cloud-config.js`. يمكن أيضاً استخدام المفتاح العام `anon` القديم. **ممنوع تماماً نشر `service_role` أو `sb_secret_...`.**
6. احفظ `cloud-config.js` وارفع ملفات التطبيق جميعاً (باستثناء `supabase_setup.sql` إن شئت) إلى جذر مستودع GitHub Pages: https://github.com/attest313/idad-mobile . راجع أن `index.html` في جذر المستودع.
7. افتح https://attest313.github.io/idad-mobile/ من Chrome على هاتف Android؛ ستظهر شاشة تسجيل الحسابات، لا بيانات محفوظة من المدرس السابق.
8. **قبل فتح التسجيل لعامة المدرسين:** أعدّ مزوّد بريد SMTP حقيقياً في إعدادات Supabase. خدمة إرسال البريد الافتراضية مخصصة للتجربة وقد ترفض عناوين المدرسين غير المصرح بها.

## تحقق حتمي قبل النشر للمدرسين

- أنشئ **حساب المدرس A** وحساب **المدرس B** على متصفحين/ملفين شخصيين مختلفين.
- سجل دخول A وأضف شعبة باسم تجريبي، وطالباً وهمياً، ونتيجة اختبار وهمية، وانتظر شارة «محفوظ سحابياً».
- سجل دخول B. يجب أن يبدأ الحساب دون شعب أو طلبة وألا تظهر بيانات A.
- أضف طالباً وهمياً إلى B ثم عد إلى A. يجب ألا تظهر سجلات B في حساب A.
- اختبر RLS فعلياً ضد SELECT وINSERT وUPDATE مع JWT حساب B على سجلات A (يجب أن تعيد SELECT صفوفاً فارغة، وأن يفشل INSERT المخالف، وألا تعدّل UPDATE أي صف)، ثم اختبر منع دور `anon`، باستخدام أدوات اختبار Supabase أو بيئة تطوير معزولة. **الفحص الظاهري للواجهة لا يكفي وحده لإثبات العزل.**
- اختبر الحفظ واستعادة البيانات، وغياب الشبكة، وتضارب تعديل المدرس نفسه من جهازين. لا تستخدم درجات حقيقية حتى تنجح الاختبارات.

## نقل بيانات الإصدار 9.2

1. افتح الإصدار القديم أولاً وصدّر نسخة JSON شاملة من **المزيد → نسخة احتياطية**. احتفظ بها خارج الهاتف.
2. حدّث GitHub Pages وشغّل 10.0 وسجّل حسابك الخاص.
3. من شاشة البداية اضغط «استعادة نسخة JSON» أو «نقل سجلات الهاتف القديم». اختر نقل البيانات إلى **حسابك أنت فقط** ثم انتظر «محفوظ سحابياً».
4. تحقق من عدد الشعب والطلبة والدرجات في الحساب السحابي.
5. بعد التأكد من وجود نسخة احتياطية، يمكن اختيار «حذف التخزين القديم بعد النقل». هذه خطوة مهمة عند مشاركة الجهاز؛ البيانات القديمة تظل خارج نظام RLS طالما بقيت في تخزين المتصفح من الإصدار السابق.

## كيفية العمل وحدوده حالياً

- يعمل تطبيق PWA عبر HTTPS على GitHub Pages، ويُثبّت على Android عبر Chrome.
- **البيانات تحتاج اتصال إنترنت.** ملفات الواجهة قد تبقى مخزنة للعمل دون شبكة، لكن العمليات السحابية لا تعمل دون اتصال. تجنّب التحرير إذا لم يظهر الحفظ السحابي.
- التخزين الحالي: **مستند JSON منفصل لكل مدرس** بحد تقريبي 5 ميغابايت لكل حساب. وهو ملائم لإطلاق محدود، لكنه ليس بعد نموذجاً علائقياً مفصّلاً للجداول والدرجات. يلزم تحويله لاحقاً إلى جداول `classes`, `students`, `assessments`, `marks`, `attendance` إذا زاد حجم البيانات أو تكررت التعديلات المتزامنة.
- يكتشف تعارضات المزامنة باستخدام رقم الإصدار؛ لا يدمج تلقائياً تغيرات جهازين مختلفين.
- يظهر البريد الإلكتروني للحساب الحالي وزر تسجيل الخروج وحالة المزامنة أعلى التطبيق.
- تجنب استخدام الهاتف المشترك مع «تذكرني». وعند انتهاء العمل اختر **تسجيل الخروج** واقفل جهازك بكلمة مرور.
- الاستيراد من Excel يفكّ الملف على الجهاز ثم يرسل السجلات المستوردة لحساب المدرس بعد التأكيد؛ ملفات GitHub المنشورة عامة وليست مكاناً لرفع قوائم الطلبة.
- بيانات الطلبة مخزنة في خادم Supabase وغير مشفرة تشفيراً طرفياً بين جهازك والسحابة؛ النقل محمي عادة عبر HTTPS وإدارة الوصول تعتمد على Auth وRLS.

## الاختبار المنجز في بيئة التطوير

- فحص بناء JavaScript لجميع الوحدات.
- اختبارات وحدة بمحاكاة خادم HTTP للحسابين المختلفين وتخزين مساحة العمل وتعارض الإصدارات وتسجيل الخروج.
- لم يُشغَّل Supabase حقيقي ولم تُجرَ بعد اختبارات RLS الحية. الاختبار التفاعلي بـChromium لم يكن متاحاً في البيئة الحالية بسبب حظر المتصفح المحلي.
- **لا تعتبر النسخة صالحة لمدرسين متعددين ببيانات حقيقية قبل استكمال الفحوص الحية أعلاه.**
